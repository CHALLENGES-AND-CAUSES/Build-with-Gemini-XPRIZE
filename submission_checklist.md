# Submission Form Checklist

This is a checklist of all the fields and materials you need to prepare for your final submission on Devpost.

## 1. General Info
* [ ] **Project name:** (Can be changed later, max 60 chars)
* [ ] **Elevator pitch:** A short tagline for the project (max 200 chars)

## 2. Project Details (Public Project Page)
* [ ] **About the project:** A Markdown-formatted story covering:
  * Inspiration
  * What you learned
  * How you built your project
  * Challenges faced
* [ ] **Built with:** Up to 25 tags (Languages, frameworks, platforms, cloud services, databases, APIs, etc.)
* [ ] **"Try it out" links:** URLs for demo site, app store listing, GitHub repo, etc.
* [ ] **Image gallery:** Up to 15 images (JPG, PNG, GIF, 5 MB max, 3:2 ratio recommended).
* [ ] **Video demo link:** Embed link (YouTube, Facebook Video, Vimeo, or Youku) for the 3-minute demo.

## 3. Additional Info (For Judges & Organizers)
### Basic Information
* [ ] **Upload a File:** (Optional/General upload field if required).
* [ ] **Start date (MM-DD-YY):** All development must be completed during the hackathon.
* [ ] **Submitter type:** Individual, team, or organization.
  * *If Organization:* Name and Employer Identification Number (EIN).
* [ ] **Country of residence:** For yourself and team members.
* [ ] **Category:** Which of the 5 categories are you submitting into?

### AI & Impact
* [ ] **Impact:** Explain how your project uses AI to impact the world, specifically in your chosen category.
* [ ] **AI Tools Used:** Which AI tools have you leveraged?
* [ ] **AI-Native Operations:** Explain how your business operates with AI (what achieves meaningful scale/impact).
* [ ] **AI in Production:** Explain the extent to which AI is live in production and executes key decisions (producing goods/services, serving customers, growing revenue).

### Google Cloud & Gemini Usage
* [ ] **Google Cloud Product:** Explain which product from Google Cloud you used and how.
* [ ] **Gemini API Usage:** Explain which LLMs are used and specifically how the Gemini API is used (you *must* use Gemini API for at least one LLM call).

### Business Model & Sustainability
* [ ] **Underlying Business Model:** Explain the business model of your submission.
* [ ] **Future Operations:** How will you sustain business operations in the future?
* [ ] **Sustainability & Viability (The 3 Requirements):**
  1. **5-year goal:** Target revenue, total addressable market (TAM), and market share.
  2. **Path to profitability:** P&L projections and when you'll hit it.
  3. **Why it's achievable:** Your hypothesis and the revenue, users, and traction seen during the hackathon.
* [ ] **Pre-existing Resources:** Are you using any pre-existing business resources (from before May 19, 2026)? E.g., employees, contact lists, existing audience. If yes, list and explain.

### Code & Evidence
* [ ] **GitHub Repo URL:** Must contain all source code. Public or Private (if private, share with `testing@devpost.com` and `judging@hacker.fund`).
* [ ] **Repo Checkbox:** Confirm repo is shared with the above emails.
* [ ] **Product Evidence Folder URL:** URL to a folder named "product evidence" in your repo containing agent execution logs, API usage records, and screenshots of dashboards.
* [ ] **Upload Evidence of Product Running:** (Allowed: pdf, png, jpg, jpeg. Max 35MB). Must include:
  * Monthly PDFs of Google Cloud billing invoices (even if $0 / free tier).
  * Screenshots of observability dashboards for any Gemini models used.
  * (Optional) Any other supporting info like logs.

### Financials & Traction (During Hackathon)
* [ ] **Total Revenue:** USD (even if $0).
* [ ] **Revenue by Month:** May, June, July, and August 2026 (e.g., "May: $0, June: $3...").
* [ ] **Revenue Explanation:** Include Price per customer, period of payment (e.g., monthly), and number of paying users/transactions.
* [ ] **Related-Party Revenue:** Revenue earned from team, family, or pre-existing relationships (even if $0).
* [ ] **Total Expenses:** Total costs incurred, USD (even if $0).
* [ ] **Total Cost of Goods Sold (COGS):** USD, plus a one-sentence description.
* [ ] **Marketing & CAC Expense:** Total marketing and customer acquisition expense, plus a description.
* [ ] **Additional Expenses:** Any missing expenses not covered, plus description.
* [ ] **Profit Evidence (P&L) Upload:** Upload a simple P&L. Template: [https://bit.ly/4w3DvwL](https://bit.ly/4w3DvwL).
* [ ] **Users Acquired:** Number of users acquired (even if 0).
* [ ] **Paying Users:** Number of users paying (even if 0).
* [ ] **Public Testimonial:** Share a verifiable testimonial by a customer/user available publicly via an online post.
* [ ] **Level of Learning:** Describe the level of learning derived from the project.
